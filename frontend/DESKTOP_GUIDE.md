# window-Stand User 桌宠使用说明

支持后台处理、逐次授权的主机桌面操作，以及可选独立虚拟机。首次配置见[新用户上手说明](../docs/GETTING_STARTED.md)。主机模式仍共用键鼠；独立虚拟机在客户机内操作。

## 启动

双击项目 `frontend/` 目录内的 **`start-desktop.vbs`**，或该目录中的“启动桌宠”快捷方式。使用项目根目录 `.venv` 中的 `pythonw.exe`，不打开终端。重复启动会呼出已有桌宠。

第一次启动先在「模型与执行」设置服务商、模型名、API Key 和可选接口地址。支持 OpenAI 兼容接口和项目已有的多种 Provider；模型必须支持工具调用。点击「测试连接与工具调用」会发起一次模型请求，但不会操作电脑。启用截图还要求模型支持图片，连接测试不验证视觉能力。

开发环境需要安装 `desktop` 依赖组：`uv sync --extra desktop --extra dev`。本项目已将其安装到 F 盘。新机器安装时应同样指定本地缓存目录与可用的 Python。

## 大脑、行动者与独立视觉

原「模型与执行」现在配置**行动者模型**。新增「大脑与视觉」页，可分别启用规划大脑和截图视觉模型，三个角色可使用不同服务商、地址和 Key；没有替你选择或覆盖已有模型。

- 大脑：填写模型后启用并保存。开局先由行动者观察/搜集，整理信息、失败恢复、循环或达到整理间隔时才调用大脑。默认每 8 步整理一次，规划最多 6 次；均可调整。
- 视觉：启用独立视觉模型，同时在执行页勾选发送截图。可用“测试图片识别”检查图片输入能力，测试只发一张程序生成的小图片，不截取你的桌面。
- 每个角色的测试结果会显示在设置页底部。测试不保存配置，修改后请点击保存。
- 勾选复用流程时，满足明确条件的机械点击可跳过模型推理；仍重新观察、定位并检查操作结果。当前不支持任意鼠标宏或所有操作的自动复用。
- 关闭独立大脑仍可使用原模型；关闭独立视觉仍可使用原模型直接看图（须支持图片）。

## 历史与记忆

默认保存**从本次更新后的新任务开始**的记录；此前未保存的会话无法补回。在「历史与记忆」选择任务，可分页查看具体观察、工具调用、结果、计划及模型用量。点击“续接为新任务”只填入任务要求，不直接操作电脑；再点击开始后会读取历史并重新观察。

同页可以切换到用户偏好，添加、更新、确认或删除偏好。模型提出的偏好先进入“待确认”，确认后才生效；已有操作权限不会因偏好改变。也可查看、删除已验证流程，验证失败的流程会被停用。

数据库为项目本地 `.windows-use/memory.sqlite3`，不保存截图。任务和界面文字仍可能包含个人信息；不要上传整个 `.windows-use/`。关闭保存记忆后，后续任务不再使用数据库，但不会删除已有历史。强制停止或程序异常结束后，任务标为取消/中断，不自动重放未知结果的动作。

设计依据、数据表、动态切换规则和实际边界见 [记忆与分层执行架构](../docs/COGNITIVE_ARCHITECTURE.md)。

## 使用方式

「模型与执行」新增操作授权，默认不允许删除、发送、付款等风险操作。保存授权后用于后续任务；未授权时会停止并说明原因。高级执行权限范围较大，说明与迁移边界见 [操作安全说明](../docs/SAFETY_MIGRATION.md)。

- 默认只显示桌宠形象，透明空白区域不占点击范围。左键点击后，下方出现「设置 / 任务」两个按钮；设置打开完整面板，任务打开紧凑圆角输入框。输入框只保留「发送」和右上角 ×，回车也可发送；× 仅关闭输入框，不退出程序。
- 点击按钮区域以外的位置时，「设置 / 任务」自动收起；点击原位置的行为仍会正常传给其他窗口。
- 桌宠形象上不显示关闭按钮。主界面内的「退出程序」会停止任务并完全退出。
- 主界面右上角 **×** 仅隐藏到系统托盘：面板、桌宠和旁观窗一起隐藏，任务继续后台运行。任务结束也不会自动弹出。
- 点击 Windows 右下角通知区域的桌宠图标可唤醒桌宠（图标可能在“^”折叠区）。右键托盘图标可直接选择「桌宠大小」，或打开模型、外观等设置。
- 拖动桌宠形象可换位置，松开后保存。运行中等待模型时仍可拖动；真正截图和执行动作期间桌宠会暂时隐藏。托盘菜单可将桌宠放回屏幕右下角。
- 开始任务后输入面板收起，桌宠用动画表达状态，旁观窗实时展示每步的计划、操作和输出。
- **Ctrl + Alt + Space** 或点击「任务」：运行时先请求暂停，待机时直接展开输入框。当前任务暂停时不能发送新任务，点击 × 关闭输入框会继续原任务。停止任务可使用托盘或 Ctrl + Alt + Esc；完整记录在图形面板的任务页。
- 在暂停面板点击「继续任务」恢复。暂停期间尚未执行的旧坐标操作会丢弃，模型重新观察后决策。
- **Ctrl + Alt + Esc**：停止当前 Agent 进程，包括等待中的模型请求。停止不能撤销已经完成的操作；已启动的外部程序或命令可能继续运行。
- 全局快捷键被占用时，可以通过系统托盘菜单呼出、停止和退出。
- 「收起为桌宠」只收起主面板，桌宠继续显示；右上角 × 和「隐藏到系统托盘」则完全隐藏界面。只有主界面「退出程序」和托盘「退出桌宠」会结束程序。

## 自定义形象

默认形象为“白金之星”，使用内置角色图片，提供悬浮、呼吸和任务状态反馈；仍可导入自定义图片或动画。

外观页左侧按实际桌宠尺寸预览，右侧设置可独立滚动，底部「保存外观」始终可见。「保存外观」只保存形象相关设置，不会顺便保存模型页尚未提交的内容；修改名称、大小或动作时不再反复解码同一张图片。

默认勾选「导入时自动去除白色背景」：去除与图片边缘相连的近白色区域，保留未与背景连通的白色细节，并裁去透明留白。白色主体与白底连成一片时可能误删，可取消勾选再导入。已有图片可点击「去除当前图片白底」，预览后保存；原文件不改写。

静态图片保存上限提高至 1024 像素，动画为 512 像素，显示端取消重复缩小并启用平滑缩放。之前压缩至 320 像素的素材无法恢复丢失的细节，需要重新导入原始图片。动画使用统一裁剪范围，避免各帧大小跳变。

可以导入 PNG、JPG、WebP 或 GIF，最大 20 MB、120 帧、1600 万像素。透明底图片效果最好。导入内容复制到本地目录，即使移动原图片也不影响使用。

- 静态图片：自动添加整体漂浮、呼吸或跳动。不自动生成新的表情、肢体或骨骼动画。
- 动图：保留帧顺序和帧时长，在本地循环播放；过快或过慢的帧时长会限制到 40–2000 ms。
- 可以分别指定待机、思考、执行、完成、异常的图片或动图。未配置的状态使用待机形象。
- 可以设置名称、大小、动作风格，或开启「减少动态」。点击「保存外观」后应用。

## 执行时如何减少干扰

新增可选 **独立虚拟机**：在「执行方式」页选择并保存，任务的截图和键鼠操作转到客户机；连接失败会停止，不回退到主机。下方可管理创建、启动、保存状态、关机、快照和停用恢复，也可直接双击 `vm/Manage-VM.vbs`。Windows ISO 需从微软官方下载，当前已配置空机但未装系统。详见 [虚拟机使用指南](../vm/README.md)。

新版默认后台优先。工作目录文本处理和网页读取不移动鼠标；需要点击、输入、滚动、切换窗口或调用未知副作用控件时，会弹出「允许本次动作 / 拒绝」卡片。关闭或两分钟未回复不会执行。批准后重新观察并核对目标；单纯移动鼠标或输入时间变化不会撤销授权。目标位置、界面或焦点确实改变时仍会停止旧动作。需要主动中止时点停止或按 Ctrl+Alt+Esc。批准只管这一步，文件写入、发送等风险权限仍单独检查。

## 定时任务

可以直接告诉桌宠「10 分钟后查看下载结果」或「今晚 18:30 帮我打开……」。模型通过 `timer_tool` 创建一次性定时任务，可查询当前时间、列出或取消任务。只有工具返回成功才表示已安排；安排完成并不表示动作已执行。

- 支持 1 秒至 30 天后的任务，或带时区的指定时间；最多 100 个待执行任务。
- 定时执行是普通任务的一种方式。在「任务」页展开「稍后执行的任务」查看或取消待执行任务；不设单独页面或托盘入口。已在执行的任务用普通停止按钮。
- 定时记录保存在 `.windows-use/timers.sqlite3`，不保存 API Key、截图坐标或桌面批准。到时使用当前已保存的模型配置，保持创建时的执行环境；风险权限取创建时与当前权限的交集。
- 等待期间不保持模型请求或客户机连接。需要保持桌宠运行，可隐藏到托盘；不注册 Windows 定时服务，不唤醒关机/休眠的电脑。
- 忙时等待空闲；超过计划时间 5 分钟的任务标为已错过，不自动补做。程序异常时已经开始的任务标为中断，不重放结果未知的操作。
- 到时重新观察界面，主机动作仍重新申请批准；虚拟机不可用不会切回主机。定时任务不能自动创建后续定时任务。

## 虚拟机设置分组

「运行状态」用于检测连接；「首次准备」按下载镜像、安装系统、启用三个步骤操作；「日常使用」提供启动、查看画面、保存停止、关机和成果目录。

「调整安装参数」「备份与恢复」「维护与排障」「停用与清理」默认折叠。点击标题展开，每组说明适用场景；删除和恢复操作仍保留确认。

设置的「执行环境」页展示规则及可选沙箱入口。沙箱不参与 Agent 自动执行，不需要安装；当前家庭版系统上不可用。详细已实现能力和限制见 [混合执行首版](../docs/HYBRID_EXECUTION_STATUS.md)。

桌宠显示时不主动获取焦点，并保留拖动能力；反馈卡片在等待模型和任务结束时接收滚轮。后台观察排除前端进程的 UIA 窗口；系统支持截图排除时，桌宠与反馈卡片保持可见。观察和执行期间两者临时穿透点击，若目标坐标落在悬浮窗区域则短暂隐藏，防止控件命中错误。不支持截图排除时回退到隐藏握手；输入面板和菜单仍会收起，确认超时则结束任务。Windows 原生透明窗口直接按透明像素处理点击范围，不再每帧修改窗口形状。

上述悬浮窗机制减少前端干扰。批准后的本机动作仍使用系统鼠标和键盘，执行期间请短暂让出输入；后台工具可以与用户同时工作，但任意 GUI 任务的完全并行尚不支持。读取画面时悬浮窗可能短暂消失；应用自身额外触发的屏幕捕获不在该握手范围内。

反馈卡片显示当前步数、观察/思考/执行阶段、阶段耗时及当前操作；同一步的计划、工具调用和结果都会更新，等待期间保留最近内容。耗时用于区分“仍在等待”与“已暂停”，并不代表模型逐 token 流式输出。最终结果保留到新任务或用户隐藏界面；完整过程在任务面板中查看。

反馈正文不再截断为 1000 字或最多 70 行。超过可见区域时，停留约 2 秒后缓慢自动滚动到末尾；鼠标悬停时暂停，手动滚轮或拖动滚动条后暂缓自动滚动约 5 秒。每条新的反馈从顶部开始。

窗口切换会确认目标确实成为前台；切换失败返回失败，目标已经在前台时会明确提示无需重复切换。

## 多显示器

控件树按真实虚拟桌面原点裁剪，支持左侧或上方副屏的负坐标；布局每次观察重新读取。鼠标先按全局物理坐标定位，再发送按键事件，不再使用主屏宽高归一化按钮坐标。定位失败时不点击旧位置。

每次模型观察包含各显示器边界、窗口位置和整桌面截图原点；截图被缩放后仍应优先使用 UIA 的全局坐标。系统拒绝直接激活窗口时，会尝试点击确认未遮挡、命中类型为标题栏的区域，不猜测网页内容区。完全被遮挡或没有可用标题栏的窗口仍可能需要手动激活。

当前本机布局为副屏在左（-1920, 0）至（0, 1080），主屏为（0, 0）至（1920, 1080）。已用独立临时窗口验证副屏真实点击与标题栏激活，未用课程任务验证业务结果。负坐标规则参见 [Microsoft 虚拟屏幕文档](https://learn.microsoft.com/windows/win32/gdi/the-virtual-screen)。

原生悬浮窗依据：[Windows 分层窗口点击穿透](https://learn.microsoft.com/windows/win32/winmsg/window-features)、[截图排除 API](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity)。不支持相关能力时保留原来的隐藏保护。

## 本地数据

以下数据路径相对项目根目录。

- `.windows-use/desktop.json`：模型与桌宠设置；API Key 使用 Windows DPAPI 按当前账号加密。
- `.windows-use/desktop-assets/`：导入后规范化的图片与动画。
- `.local/`：临时文件、依赖缓存和启动失败日志。
- 执行记录默认只保存在内存中，最多保留最近 500 条；可手动导出文本。

首次启动会尝试导入已有终端的活动模型配置。桌宠之后使用独立配置，不回写 CLI 配置。Key 加密数据复制到另一台机器或换 Windows 用户后可能无法解密，需要重新填写。

桌宠图片仅在本地导入处理，不调用生成模型，也不上传图片。执行任务时，桌面状态以及按需开启的截图会发送给所配置的模型服务。

## 开发结构与验证

以下源码路径相对 `frontend/`。在项目根目录运行 `.venv\Scripts\python.exe -m pytest frontend/tests`。

- `desktop_app/app.py`：任务生命周期、暂停恢复、托盘、截图握手和单实例。
- `desktop_app/widgets.py`、`pet.py`：原生 PySide6 界面、默认角色与逐帧动画。
- `desktop_app/process.py`、`worker.py`：QProcess + JSON Lines，Agent 在独立进程主线程使用 UIA。
- `desktop_app/settings.py`：本地配置、凭据加密、图片验证和导入。
- `start-desktop.pyw`、`start-desktop.vbs`：无终端的本地启动入口。
- `tests/`：配置与图片往返、暂停边界、采集握手、Unicode 消息分片和停止阻塞进程的测试。

真实模型、实际桌面焦点与多屏表现仍需在用户会话中验收；离屏界面测试和模拟进程测试不代表真实业务任务已完成。
