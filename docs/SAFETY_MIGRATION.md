# 操作安全：arc-cua 参考与迁移

## 来源与适用范围

参考本地 `arc-cua-master/src/arc_cua/safety.py`、`runtime.py`、`policies/choice.py`、`docs/internals.md` 及 `tests/test_safety.py`。风险词表与递归脱敏逻辑基于该项目改编，MIT 许可保留于 [arc-cua-LICENSE.txt](third-party/arc-cua-LICENSE.txt)。运行时不依赖 arc-cua，也未复制其 macOS 后端。

保护接入本项目工具注册器，桌宠、CLI 和 Python API 的默认 Agent 均生效；同步和异步执行走相同规则。直接调用底层 Desktop 或 Tool 的开发者代码不经过注册器，因此不受这些保护约束。

## 迁移对照

| arc-cua 机制 | 本项目落地情况 |
| --- | --- |
| delete / send / purchase / close 风险词表 | 已迁移；英文完整词匹配，增加中文风险短语。中文采用子串匹配，可能误拦截 |
| 不向模型提供未授权风险控件 | 已在 UIA 文本候选列表过滤，保留原索引；截图仍可能包含这些控件，因此执行层再次检查 |
| 执行前再次检查风险 | 已接入 Registry.execute / aexecute；拒绝后结束任务，不让模型换工具绕行 |
| 调用方显式 allowed_risks | 已加入 Agent 参数及图形设置；自然语言任务或模型输出不会自动扩大权限 |
| 敏感输入值递归脱敏 | 已用于注册的 secrets：模型文本消息、上下文压缩请求、事件、invoke/ainvoke 返回内容及主要遥测文本；桌宠自动注册填写的模型 Key |
| 操作目标新鲜度检查 | 坐标点击/输入执行前比对前台窗口、UIA RuntimeId、名称和边界；不一致或校验异常时不执行，返回重新观察要求 |
| 操作消费后不可重放 | 点击/输入调用前消费当前快照，即使工具抛出异常，也不允许凭同一快照再次操作 |
| 步数限制、循环检测、取消 | 沿用现有 max_steps、连续失败上限、LoopGuard、桌宠暂停与停止；LoopGuard 主要提供循环提示，不等同于 arc-cua 的无变化硬停止 |
| 置信度 / margin 阈值 | 未迁移：当前 Provider 没有统一、可比较的决策置信度字段 |
| 独立完成条件验证、截图复核 | 未迁移：当前 done_tool 仍是模型声明完成，不能视为业务结果已验证 |
| 语义/视觉双后端保护、settle 等待、任务总超时 | 未完整迁移；当前主要是 UIA 语义校验，无视觉目标指纹及独立硬超时 |
| secret_inputs 引用后在执行端填入真实值 | 未迁移：没有登录凭据保险箱或安全输入引用协议，不应把密码直接写进任务文本 |

## 默认行为与授权

在桌宠「模型与执行」中选择授权并保存，随后启动新任务。授权会保存在本机设置中，用于后续任务；运行中的任务不会因修改文件而得到额外权限。默认全部不勾选。

| 权限 | 控制范围 |
| --- | --- |
| delete | 命中风险标签的删除/清空点击、Delete 快捷键、文件和记忆删除 |
| send | 命中风险标签的发送/发布/分享点击 |
| purchase | 命中风险标签的购买/支付/转账点击 |
| close | 命中风险标签的关闭/退出点击、关闭窗口快捷键、移除虚拟桌面 |
| file_write | 文件/记忆写入、覆盖、更新、移动、复制 |
| system | Shell、提交/粘贴等非白名单快捷键、输入后回车、批量操作、拖拽和未分类自定义工具 |
| unverified | 没有对应 UIA 交互控件的坐标点击/输入；放弃此类目标的标签与新鲜度保证 |

`system` 是高级授权：Shell 和快捷键可以间接删除、发送、支付，所以不能将其他四类开关理解为启用 system 后仍不可绕过的隔离边界。默认限制 Shell 的所有命令，而非用危险命令关键词猜测安全性。

Python API 示例：`Agent(llm=llm, allowed_risks=("send",))`。CLI 当前没有交互式授权菜单，使用默认权限；遇到拦截可改用桌宠或通过 API 明确授权。未知权限名会在初始化时被拒绝。

拦截分两种：

- 未授权操作：结束当前任务，输出原因。没有自动弹出抢焦点确认框，也不会在后台自动重试。
- 目标变化/校验失败/旧快照重放：当前动作不执行，交给下一轮重新观察，仍受连续失败和步数上限约束。

## 保护边界

这是一层执行防护，不是 Windows 权限沙箱，也不保证理解所有界面的真实意图。无风险关键词的图标、自定义画布、含糊的“确定”按钮、输入框触发的脚本行为都可能没有正确风险分类。检查与点击之间仍存在很短的竞争窗口；UIA 查询本身也可能阻塞。

脱敏只覆盖调用方明确注册的字面值，不自动发现所有密码，不遮挡截图像素，不保证第三方 SDK 自己的日志或编码后的秘密会被识别。图片、任意文件读取及网络抓取并未增加 DLP 防护。模型 API Key 在认证请求中仍会正常发送给所配置的服务。

前台窗口检查较严格，多窗口、浏览器子控件以及 UIA 不完整的应用可能被拒绝。需通过真实桌面试用确认兼容性。原有截图握手、穿透、不抢焦点和停止快捷键保留；本机鼠标共用问题仍需可选虚拟机方案解决。

## 验证

`tests/test_safety.py` 使用模拟工具和模型覆盖中英文分类、双执行入口、未授权拒绝、目标变化、旧快照防重放、候选过滤、事件与模型消息脱敏，以及 Agent 拒绝后不再请求模型。测试不执行真实键鼠、文件删除或外部模型请求。

运行测试前将 `WINDOWS_USE_HOME` 指向项目内测试目录，并设置 `ANONYMIZED_TELEMETRY=false`、`LITELLM_LOCAL_MODEL_COST_MAP=True`，再执行 `.venv\Scripts\python.exe -m pytest tests/test_safety.py frontend/tests/test_ui.py frontend/tests/test_control.py`。
